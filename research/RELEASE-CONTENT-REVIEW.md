## Helper and permission boundary

The GUI and engine declare `audio-input`; the engine and plugin host declare `disable-library-validation`. No App Sandbox entitlement is present. Apple describes these as access to Core Audio input and an exception allowing third-party plugin/library loading respectively: [audio input](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.device.audio-input), [library validation](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.cs.disable-library-validation). The actual binaries' entitlements are retained in the signing record. Their presence does not establish TCC consent or correct packaged-helper privacy attribution.

Helpers use ordinary same-user `Process` execution, with bounded IPC; there is no privileged service, administrator escalation or automatic privacy grant. Audio Units are selected by installed component identity rather than executable paths imported from a studio. Plugins still execute with the helper's user privileges. Process crash containment is not a security sandbox. Enclosing-app microphone/system-capture descriptions and the absence of a recording entitlement on the plugin probe do not prove all runtime privacy outcomes.

One concrete defect exists at this checkpoint: `EngineClient.defaultHelperURL()` searches ancestor directories when the expected bundled helper is missing. An intact app resolves the embedded helper first, but a damaged package can select a different same-named executable outside its bundle. Packaged resolution should fail closed; explicit development/test helper injection can remain. This is a repair finding, not evidence of an observed external execution or a remotely supplied studio path.

A subsequent uncommitted repair uses a shared resolver for both helpers. Five path-control tests cover the expected embedded location, damaged/missing/non-file helpers, symlink substitutions, whole-app aliases, executable-derived application identity and SwiftPM discovery. The focused resolver/plugin/engine protocol and process suite passed 31 tests in four suites; hardware and opt-in Apple probe cases remained disabled. That development result does not retroactively repair the preserved f733 binary, and path validation does not authenticate an executable's signature.
